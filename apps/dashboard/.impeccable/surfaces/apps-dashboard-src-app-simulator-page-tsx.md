# Protected simulated Alexa+ client

## Scope and mode

- Target: `apps/dashboard/src/app/simulator/page.tsx`
- Mode: Explain + Operate
- Audience: the single authenticated operator and hackathon evaluator
- Job: prove the fallback client reaches the same real MCP preparation/status boundary without claiming Alexa hosting or account linking
- Primary action: submit one desired checkout outcome to create a bounded proposal that stops at `AWAITING_APPROVAL`
- Proof: validated MCP output, durable work reference, and an independently readable status
- Constraint: no approval, amendment, execution, deployment, or merge controls; no bearer reaches the browser

## Direction contract

**THESIS:** Let a simulated Alexa+ surface capture only the outcome while Mandate visibly owns every authority decision.

**OWN-WORLD:** Extend the pinned near-black mission-control instrument with broad graphite regions, steel hairlines, compact Inter, cyan only for the live in-scope MCP path, amber for waiting review, and green only for independently verified completion.

**STORY:** The operator first sees connection truth, states an outcome, receives the simulated conversational readback, inspects the real immutable authority summary, and can later retrieve the same reference without gaining an approval control.

**FIRST VIEWPORT:** A sparse thesis and connection-truth ledger lead into one two-column instrument: conversation on the left, immutable authority on the right.

**FORM:** Conversation instrument with an attached authority envelope; a direct extension of the established public/demo visual world rather than a new aesthetic.

**FINISH:** complete only after strict MCP validation, responsive browser review, authentication-boundary tests, documentation, and explicit claim labeling

## Memorable moment

A human enters only a plain-language outcome; the right side resolves into a fixed server-owned authority envelope and stops in amber at human review.

## Fixed decisions

- The route is protected by the existing single-operator Basic-auth boundary.
- The production server uses the existing principal-bound development credential; the browser never receives it.
- Illustrative mode disables preparation.
- The real Alexa+ route remains primary but externally blocked on Amazon account onboarding.
